每个任务先出路线卡、用户点了「开工」才解锁执行类工具；工具调用有预算，超线就逼收尾。

主线：一条消息怎么走到工具执行

上排从左到右是「判定与出卡」，下排从右到左是「确认、解锁、执行、计数」。闸门在 tools/pre-execute，不依赖模型自觉。

插件 DSH 运行时 界面 闸门 / 状态 用户

四条硬口径

这些是设计参数，写进 Config，装完能在设置页改。

触发规则（auto 默认）

  • 新会话第一条、带执行动词的新任务：弹卡确认
  • 「继续 / 好 / 改一下」这类接续句：只出一行路线卡，不拦
  • 点「开工 · 按推荐」才解闸；要改路线点「先改路线」
  • 本会话免确认走 /route off，新会话自动恢复

硬闸口径

  • 拦：write / edit / bash / pwsh / subagent
  • 放：read / grep / glob / web_search / web_fetch
  • 生效点是 tools/pre-execute 的返回值，不靠模型自觉

预算

  • 计划期：最多 4 次只读探查就要出卡
  • 执行期：每回合 12 次工具，80% 提醒、100% 要收尾
  • 到线返回可读理由，不硬断回合

借鉴来源

  • spec-kit：阶段闸门，先定再动手
  • Cline：Plan/Act 双模式 + 工具白名单
  • Roo Code：子任务隔离上下文（已归档，只借思想）
  • humanlayer：人工审批闸门 allow / reject
